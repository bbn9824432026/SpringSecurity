## Layer 1: The Foundation — `Authentication` and `SecurityContext`

Before anything else, you need to understand what Spring Security is fundamentally *transporting* throughout the entire authentication lifecycle: the `Authentication` object. Everything else is infrastructure built to create, validate, store, and retrieve this one object.

```java
/**
 * LAYER 1: The Core Contract — Authentication
 *
 * Authentication is the central abstraction Spring Security uses to represent
 * "who is making this request, and are they verified?"
 *
 * It has a dual lifecycle:
 *   BEFORE auth: principal=username(String), credentials=password, authenticated=false
 *   AFTER auth:  principal=UserDetails, credentials=null (erased!), authenticated=true
 *
 * Internal consumer: AbstractAuthenticationProcessingFilter reads the returned
 * Authentication from AuthenticationManager and hands it to SecurityContextHolder.
 */
public interface Authentication extends Principal, Serializable {

    // The "who" — String username before auth, UserDetails object after auth
    Object getPrincipal();

    // The "proof" — raw password before auth, null after (credentials are erased for security)
    Object getCredentials();

    // Extra info — WebAuthenticationDetails (IP, sessionId) attached by the filter
    Object getDetails();

    // Granted roles/permissions — empty before auth, populated after
    Collection<? extends GrantedAuthority> getAuthorities();

    // The key flag — false when submitted, true only after AuthenticationManager verifies
    boolean isAuthenticated();

    // Framework calls setAuthenticated(false) to "untrust" a token,
    // setAuthenticated(true) is restricted to trusted internal classes
    void setAuthenticated(boolean isAuthenticated) throws IllegalArgumentException;
}
```

The `SecurityContext` is simply a holder for the current `Authentication`. Think of it as a thread-local envelope:

```java
/**
 * SecurityContext = envelope holding Authentication for a single thread.
 *
 * SecurityContextHolder = the static thread-local registry that gives any code
 * in the application access to the current user without passing it as a parameter.
 *
 * Strategy options (configured via SecurityContextHolder.setStrategyName()):
 *   - MODE_THREADLOCAL (default) — one context per thread, safe for servlet containers
 *   - MODE_INHERITABLETHREADLOCAL — child threads inherit parent's context (async tasks)
 *   - MODE_GLOBAL — single JVM-wide context (desktop apps only, never web)
 */

// Reading the current user anywhere in your application:
Authentication auth = SecurityContextHolder.getContext().getAuthentication();
String username = auth.getName(); // delegates to principal.toString() or UserDetails.getUsername()

// The SecurityContext interface itself is minimal:
public interface SecurityContext extends Serializable {
    Authentication getAuthentication();
    void setAuthentication(Authentication authentication);
}
```

**Why this matters internally:** The `successfulAuthentication()` method in `AbstractAuthenticationProcessingFilter` calls `SecurityContextHolder.getContext().setAuthentication(authResult)` — this single line is what makes the user "logged in" for the duration of the request thread.

## Layer 2: `UserDetails` and `UserDetailsService` — The Identity Contract

This is the contract between Spring Security and *your application's user model*. Spring Security doesn't know what your `User` entity looks like — it only cares about `UserDetails`.

```java
/**
 * LAYER 2A: UserDetails — The identity object Spring Security works with.
 *
 * DaoAuthenticationProvider calls loadUserByUsername(), gets back UserDetails,
 * then runs all its checks against this object.
 *
 * IMPORTANT: After successful authentication, the UserDetails object *becomes*
 * the principal inside the Authentication token. That's why you can do:
 *
 *   UserDetails user = (UserDetails) SecurityContextHolder.getContext()
 *                                       .getAuthentication().getPrincipal();
 */
public interface UserDetails extends Serializable {
    String getUsername();
    String getPassword();           // Encoded password — BCrypt, Argon2, etc.
    Collection<? extends GrantedAuthority> getAuthorities(); // Roles/permissions

    // These four flags are checked by DefaultPreAuthenticationChecks
    // and DefaultPostAuthenticationChecks inside DaoAuthenticationProvider:
    boolean isEnabled();                // false → DisabledException thrown
    boolean isAccountNonExpired();      // false → AccountExpiredException thrown
    boolean isAccountNonLocked();       // false → LockedException thrown
    boolean isCredentialsNonExpired();  // false → CredentialsExpiredException thrown
}
```

Now let's implement this with a realistic production-grade custom `UserDetails`:

```java
/**
 * Production-grade UserDetails implementation.
 *
 * Best practice: don't expose your JPA Entity as UserDetails directly.
 * Wrap it in a dedicated class so your domain model stays decoupled from
 * Spring Security's contracts.
 *
 * The UserPrincipal acts as an adapter between your domain User and Spring Security.
 */
@Getter
public final class UserPrincipal implements UserDetails {

    private final Long id;              // Your domain ID — accessible after login
    private final String username;
    private final String password;
    private final String email;
    private final boolean enabled;
    private final boolean accountNonLocked;
    private final Collection<GrantedAuthority> authorities;

    // Static factory method — construct from your domain entity
    public static UserPrincipal from(User user) {
        List<GrantedAuthority> authorities = user.getRoles().stream()
            .map(role -> new SimpleGrantedAuthority("ROLE_" + role.getName()))
            .collect(Collectors.toList());

        return new UserPrincipal(
            user.getId(), user.getUsername(), user.getPassword(),
            user.getEmail(), user.isEnabled(), !user.isLocked(), authorities
        );
    }

    @Override public boolean isAccountNonExpired() { return true; }  // Implement if you track expiry
    @Override public boolean isCredentialsNonExpired() { return true; } // Implement for forced resets
}

/**
 * LAYER 2B: UserDetailsService — The single method that bridges your DB to Spring Security.
 *
 * DaoAuthenticationProvider calls this during every authentication attempt.
 * Throw UsernameNotFoundException if the user doesn't exist — Spring Security
 * handles it and converts it to a BadCredentialsException (to prevent username enumeration).
 */
@Service
@RequiredArgsConstructor
public class CustomUserDetailsService implements UserDetailsService {

    private final UserRepository userRepository;

    @Override
    public UserDetails loadUserByUsername(String username) throws UsernameNotFoundException {
        // Username can be email or actual username — your choice
        User user = userRepository.findByUsernameOrEmail(username, username)
            .orElseThrow(() ->
                new UsernameNotFoundException("User not found: " + username));

        return UserPrincipal.from(user);
    }
}

/**
 * LAYER 2C: UserDetailsPasswordService — Optional extension point.
 *
 * If you implement this, DaoAuthenticationProvider will automatically upgrade
 * legacy password encodings (e.g., MD5 → BCrypt) on successful login.
 * This is how you do zero-downtime password hash migrations in production.
 */
@Service
@RequiredArgsConstructor
public class CustomUserDetailsService implements UserDetailsService, UserDetailsPasswordService {

    private final UserRepository userRepository;
    private final PasswordEncoder passwordEncoder;

    @Override
    public UserDetails updatePassword(UserDetails user, String newEncodedPassword) {
        // Called by DaoAuthenticationProvider when it detects the stored password
        // uses a deprecated encoding. Update your DB here.
        userRepository.updatePassword(user.getUsername(), newEncodedPassword);
        return user; // Return updated UserDetails
    }
}
```

## Layer 3: `GrantedAuthority` and Role Hierarchy

```java
/**
 * LAYER 3: GrantedAuthority — The permission atom.
 *
 * Every authorization decision in Spring Security boils down to:
 * "does the current Authentication's authorities collection contain X?"
 *
 * SimpleGrantedAuthority is the standard implementation for role strings.
 * Convention: ROLE_ prefix for roles, no prefix for fine-grained permissions.
 */

// Simple role-based authorities
new SimpleGrantedAuthority("ROLE_ADMIN")
new SimpleGrantedAuthority("ROLE_USER")

// Fine-grained permission authorities (used with @PreAuthorize("hasAuthority(...)"))
new SimpleGrantedAuthority("user:read")
new SimpleGrantedAuthority("user:write")
new SimpleGrantedAuthority("order:delete")

/**
 * RoleHierarchy — Advanced: define ROLE_ADMIN includes ROLE_USER automatically.
 *
 * Without this, hasRole('USER') returns false for an admin.
 * With this, roles cascade down the hierarchy.
 *
 * Internal consumer: RoleHierarchyVoter and RoleHierarchyAuthoritiesMapper
 */
@Bean
public RoleHierarchy roleHierarchy() {
    RoleHierarchyImpl hierarchy = new RoleHierarchyImpl();
    hierarchy.setHierarchy("""
        ROLE_ADMIN > ROLE_MANAGER
        ROLE_MANAGER > ROLE_USER
        ROLE_USER > ROLE_GUEST
        """);
    return hierarchy;
}

@Bean
public DefaultWebSecurityExpressionHandler expressionHandler() {
    DefaultWebSecurityExpressionHandler handler = new DefaultWebSecurityExpressionHandler();
    handler.setRoleHierarchy(roleHierarchy()); // Wire hierarchy into SpEL expressions
    return handler;
}
```

## Layer 4: `PasswordEncoder` — The Password Contract

```java
/**
 * LAYER 4: PasswordEncoder — How Spring Security handles passwords safely.
 *
 * DaoAuthenticationProvider calls:
 *   passwordEncoder.matches(rawPassword, storedEncodedPassword)
 *
 * NEVER store or compare raw passwords. Always use PasswordEncoder.
 *
 * DelegatingPasswordEncoder is the production default — it stores passwords
 * with a {encoderId} prefix so you can migrate algorithms over time:
 *   {bcrypt}$2a$10$...   → BCryptPasswordEncoder
 *   {argon2}$argon2id... → Argon2PasswordEncoder
 *   {noop}plaintext      → NoOpPasswordEncoder (dev only!)
 */

// Production-grade: BCrypt with explicit strength (cost factor)
@Bean
public PasswordEncoder passwordEncoder() {
    // Strength 12 → ~300ms per hash on modern hardware. Good for most production apps.
    // Strength 10 is the default (~100ms). Increase over time as hardware improves.
    return new BCryptPasswordEncoder(12);
}

// Enterprise-grade: DelegatingPasswordEncoder — supports multiple algorithms simultaneously
// This is what PasswordEncoderFactories.createDelegatingPasswordEncoder() returns
@Bean
public PasswordEncoder delegatingPasswordEncoder() {
    Map<String, PasswordEncoder> encoders = new HashMap<>();
    encoders.put("bcrypt", new BCryptPasswordEncoder(12));
    encoders.put("argon2", new Argon2PasswordEncoder(16, 32, 1, 65536, 10));
    encoders.put("scrypt", SCryptPasswordEncoder.defaultsForSpringSecurity_v5_8());

    // "bcrypt" is the default for new passwords. Old {argon2} passwords still verify.
    return new DelegatingPasswordEncoder("bcrypt", encoders);
}

// Encoding a new password (in your registration service):
@Service
@RequiredArgsConstructor
public class UserRegistrationService {
    private final PasswordEncoder passwordEncoder;
    private final UserRepository userRepository;

    public User register(RegisterRequest req) {
        User user = new User();
        user.setUsername(req.getUsername());
        // Always encode before saving — never store raw password
        user.setPassword(passwordEncoder.encode(req.getPassword()));
        return userRepository.save(user);
    }
}
```

## Layer 5: `AuthenticationProvider` — The Core Authentication Engine

This is the heart of the verification logic. `DaoAuthenticationProvider` is the default implementation that orchestrates all the checks you see in the flow diagram.

```java
/**
 * LAYER 5A: AuthenticationProvider — The contract every auth mechanism implements.
 *
 * ProviderManager iterates through a list of AuthenticationProviders.
 * Each provider declares which token types it can handle via supports().
 * The first provider that supports the token type attempts authentication.
 *
 * Internal flow: ProviderManager.authenticate() → iterates providers →
 *   calls supports(authentication.getClass()) → if true, calls authenticate()
 */
public interface AuthenticationProvider {
    // Perform authentication. Return fully authenticated token or throw exception.
    Authentication authenticate(Authentication authentication) throws AuthenticationException;

    // Declare which Authentication subclasses this provider handles.
    // DaoAuthenticationProvider returns: UsernamePasswordAuthenticationToken.class.isAssignableFrom(auth)
    boolean supports(Class<?> authentication);
}

/**
 * LAYER 5B: Custom AuthenticationProvider — when you need custom auth logic.
 *
 * Use cases:
 *   - Two-factor authentication check
 *   - LDAP/Active Directory authentication
 *   - API key authentication
 *   - IP-restricted authentication
 *   - Custom account lockout with Redis-backed attempt tracking
 */
@Component
@RequiredArgsConstructor
public class CustomDaoAuthenticationProvider implements AuthenticationProvider {

    private final CustomUserDetailsService userDetailsService;
    private final PasswordEncoder passwordEncoder;
    private final LoginAttemptService loginAttemptService; // Your custom service

    @Override
    public Authentication authenticate(Authentication authentication)
            throws AuthenticationException {

        String username = authentication.getName();
        String rawPassword = authentication.getCredentials().toString();

        // Custom pre-check: IP-based rate limiting (not in DaoAuthenticationProvider by default)
        WebAuthenticationDetails details = (WebAuthenticationDetails) authentication.getDetails();
        if (loginAttemptService.isBlocked(details.getRemoteAddress())) {
            throw new LockedException("Too many failed attempts from this IP.");
        }

        // Load user — UsernameNotFoundException is caught and re-thrown as
        // BadCredentialsException by the framework to prevent username enumeration
        UserDetails userDetails;
        try {
            userDetails = userDetailsService.loadUserByUsername(username);
        } catch (UsernameNotFoundException ex) {
            loginAttemptService.recordFailure(details.getRemoteAddress());
            throw new BadCredentialsException("Bad credentials");
        }

        // Pre-auth checks (enabled, non-expired, non-locked)
        if (!userDetails.isEnabled()) throw new DisabledException("Account disabled");
        if (!userDetails.isAccountNonLocked()) throw new LockedException("Account locked");
        if (!userDetails.isAccountNonExpired()) throw new AccountExpiredException("Account expired");

        // Password verification
        if (!passwordEncoder.matches(rawPassword, userDetails.getPassword())) {
            loginAttemptService.recordFailure(details.getRemoteAddress());
            throw new BadCredentialsException("Bad credentials");
        }

        // Post-auth checks
        if (!userDetails.isCredentialsNonExpired()) {
            throw new CredentialsExpiredException("Password expired — please reset");
        }

        loginAttemptService.clearFailures(details.getRemoteAddress());

        // Return the FULLY AUTHENTICATED token
        // Note: credentials set to null — erase raw password from memory!
        return new UsernamePasswordAuthenticationToken(
            userDetails,      // principal — UserDetails object
            null,             // credentials — null after auth (erased!)
            userDetails.getAuthorities()
        );
    }

    @Override
    public boolean supports(Class<?> authentication) {
        return UsernamePasswordAuthenticationToken.class.isAssignableFrom(authentication);
    }
}
```

## Layer 6: `UsernamePasswordAuthenticationToken` — The Token Lifecycle

```java
/**
 * LAYER 6: UsernamePasswordAuthenticationToken — the Authentication implementation
 * for username/password form login.
 *
 * It has TWO constructors with critically different semantics:
 *
 *   Constructor 1 (2-arg): Creates an UNAUTHENTICATED token (authenticated=false)
 *     — Used by UsernamePasswordAuthenticationFilter to wrap the submitted credentials
 *
 *   Constructor 2 (3-arg): Creates an AUTHENTICATED token (authenticated=true)
 *     — Used by DaoAuthenticationProvider to return the verified result
 *
 * This two-constructor pattern is the framework's way of making the distinction
 * between "credentials submitted for verification" vs "identity confirmed" explicit.
 */

// Inside UsernamePasswordAuthenticationFilter.attemptAuthentication():
// Creates the unverified token to hand to AuthenticationManager:
UsernamePasswordAuthenticationToken unverifiedToken =
    new UsernamePasswordAuthenticationToken(username, password);
//  principal=String("alice"), credentials=String("secret"), authenticated=false

// Inside DaoAuthenticationProvider.createSuccessAuthentication():
// Creates the verified token after all checks pass:
UsernamePasswordAuthenticationToken verifiedToken =
    new UsernamePasswordAuthenticationToken(userDetails, null, authorities);
//  principal=UserDetails, credentials=null, authenticated=true

/**
 * WebAuthenticationDetails — attached to the token via setDetails().
 * Captures the HTTP request context at the moment of authentication.
 *
 * Useful for: audit logging, IP-based rate limiting, session binding.
 */
public class WebAuthenticationDetails implements Serializable {
    private final String remoteAddress; // Client IP
    private final String sessionId;     // Session ID at time of auth (null if no session yet)
}

// Accessing it after login (e.g., in a success handler or audit service):
Authentication auth = SecurityContextHolder.getContext().getAuthentication();
WebAuthenticationDetails details = (WebAuthenticationDetails) auth.getDetails();
String clientIp = details.getRemoteAddress();
```

## Layer 7: `AuthenticationManager` and `ProviderManager` — The Orchestration Layer

```java
/**
 * LAYER 7: ProviderManager — the standard AuthenticationManager implementation.
 *
 * It holds an ordered list of AuthenticationProviders and tries each one.
 * It also supports a PARENT ProviderManager — if no local provider handles
 * the token, it delegates to the parent. This is how Spring Security supports
 * multiple security filter chains (one parent, multiple children).
 *
 * ProviderManager also has an eraseCredentialsAfterAuthentication flag (default: true).
 * After successful authentication, it calls token.eraseCredentials() to null out
 * the raw password, preventing it from lingering in memory or being serialized.
 */
@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public AuthenticationManager authenticationManager(
            UserDetailsService userDetailsService,
            PasswordEncoder passwordEncoder) {

        DaoAuthenticationProvider provider = new DaoAuthenticationProvider();
        provider.setUserDetailsService(userDetailsService);
        provider.setPasswordEncoder(passwordEncoder);

        // hideUserNotFoundExceptions=true (default): converts UsernameNotFoundException
        // to BadCredentialsException — prevents attackers from discovering valid usernames
        provider.setHideUserNotFoundExceptions(true);

        // Wire custom post-auth processors if needed:
        // provider.setAuthoritiesMapper(grantedAuthoritiesMapper());
        // provider.setPreAuthenticationChecks(myChecks);
        // provider.setPostAuthenticationChecks(myChecks);

        ProviderManager manager = new ProviderManager(provider);
        manager.setEraseCredentialsAfterAuthentication(true); // Always true in production!
        return manager;
    }

    /**
     * Multi-provider setup — useful when you support multiple auth mechanisms.
     * ProviderManager tries them in order. First successful result wins.
     * If all providers throw, the last exception is re-thrown.
     */
    @Bean
    public AuthenticationManager multiProviderAuthManager(
            UserDetailsService userDetailsService,
            PasswordEncoder passwordEncoder,
            LdapAuthenticationProvider ldapProvider) {

        DaoAuthenticationProvider dbProvider = new DaoAuthenticationProvider();
        dbProvider.setUserDetailsService(userDetailsService);
        dbProvider.setPasswordEncoder(passwordEncoder);

        // ProviderManager tries ldapProvider first, falls back to dbProvider
        return new ProviderManager(List.of(ldapProvider, dbProvider));
    }
}
```

## Layer 8: `UsernamePasswordAuthenticationFilter` — The HTTP Entry Point

This is where the HTTP request is transformed into an `Authentication` object. Understanding this filter is key to the entire flow.

```java
/**
 * LAYER 8A: UsernamePasswordAuthenticationFilter — extends AbstractAuthenticationProcessingFilter
 *
 * Positioned in the Spring Security filter chain at a fixed order.
 * Only activates for requests matching the login URL (default: POST /login).
 *
 * The filter chain order (simplified):
 *   SecurityContextPersistenceFilter → UsernamePasswordAuthenticationFilter
 *   → ExceptionTranslationFilter → FilterSecurityInterceptor
 */

// Default behavior — understanding what it does internally:
public class UsernamePasswordAuthenticationFilter
        extends AbstractAuthenticationProcessingFilter {

    public static final String SPRING_SECURITY_FORM_USERNAME_KEY = "username";
    public static final String SPRING_SECURITY_FORM_PASSWORD_KEY = "password";

    // Called only when requiresAuthentication() returns true (POST /login)
    @Override
    public Authentication attemptAuthentication(HttpServletRequest request,
                                                HttpServletResponse response)
            throws AuthenticationException {

        // Reject non-POST requests to the login URL
        if (this.postOnly && !request.getMethod().equals("POST")) {
            throw new AuthenticationServiceException("Only POST supported");
        }

        // Extract credentials from form body (application/x-www-form-urlencoded)
        String username = obtainUsername(request); // request.getParameter("username")
        String password = obtainPassword(request); // request.getParameter("password")
        username = username != null ? username.trim() : "";
        password = password != null ? password : "";

        // Create unauthenticated token
        UsernamePasswordAuthenticationToken authRequest =
            UsernamePasswordAuthenticationToken.unauthenticated(username, password);

        // Attach HTTP context details (IP, session ID) via WebAuthenticationDetailsSource
        setDetails(request, authRequest);
        // → authRequest.setDetails(new WebAuthenticationDetails(request))

        // Delegate to AuthenticationManager — this is where DaoAuthenticationProvider runs
        return this.getAuthenticationManager().authenticate(authRequest);
    }
}

/**
 * LAYER 8B: Custom UsernamePasswordAuthenticationFilter
 *
 * Customize when you need:
 *   - JSON body login (instead of form params)
 *   - Additional fields (tenant ID, CAPTCHA token, device fingerprint)
 *   - Custom URL matching logic
 */
@Component
public class JsonLoginAuthenticationFilter extends UsernamePasswordAuthenticationFilter {

    private final ObjectMapper objectMapper;

    public JsonLoginAuthenticationFilter(AuthenticationManager authenticationManager,
                                          ObjectMapper objectMapper) {
        super(authenticationManager);
        this.objectMapper = objectMapper;
        // Override the default /login POST matcher
        setRequiresAuthenticationRequestMatcher(
            new AntPathRequestMatcher("/api/auth/login", "POST"));
    }

    @Override
    public Authentication attemptAuthentication(HttpServletRequest request,
                                                HttpServletResponse response)
            throws AuthenticationException {
        try {
            // Parse JSON body instead of form params
            LoginRequest loginRequest = objectMapper.readValue(
                request.getInputStream(), LoginRequest.class);

            UsernamePasswordAuthenticationToken token =
                UsernamePasswordAuthenticationToken.unauthenticated(
                    loginRequest.getUsername(), loginRequest.getPassword());

            setDetails(request, token);
            return getAuthenticationManager().authenticate(token);

        } catch (IOException e) {
            throw new AuthenticationServiceException("Failed to parse login request", e);
        }
    }

    @Data
    static class LoginRequest {
        private String username;
        private String password;
    }
}
```

## Layer 9: `AbstractAuthenticationProcessingFilter` — The Template Pattern Backbone

```java
/**
 * LAYER 9: AbstractAuthenticationProcessingFilter — Template Method pattern.
 *
 * This abstract superclass handles everything EXCEPT the actual authentication logic.
 * Subclasses only implement attemptAuthentication().
 *
 * The doFilter() template method:
 *   1. requiresAuthentication()? → proceed or skip to next filter
 *   2. attemptAuthentication() → [subclass logic]
 *   3. SUCCESS → successfulAuthentication()
 *      FAILURE → unsuccessfulAuthentication()
 *
 * Key extension points developers can customize:
 */

// Inside doFilter() — the full template flow:
private void doFilter(HttpServletRequest request, HttpServletResponse response,
                      FilterChain chain) throws IOException, ServletException {

    // Step 1: Should this filter handle this request?
    if (!requiresAuthentication(request, response)) {
        chain.doFilter(request, response); // Pass through to next filter
        return;
    }

    try {
        // Step 2: Attempt authentication (implemented by subclass)
        Authentication authResult = attemptAuthentication(request, response);
        if (authResult == null) return; // Subclass signals "not done yet" (multi-step auth)

        // Step 3a: Handle session fixation and security context persistence
        this.sessionStrategy.onAuthentication(authResult, request, response);

        // Step 3b: Success path
        successfulAuthentication(request, response, chain, authResult);

    } catch (AuthenticationException ex) {
        // Step 3c: Failure path
        unsuccessfulAuthentication(request, response, ex);
    }
}

// successfulAuthentication() — what happens after DaoAuthenticationProvider succeeds:
protected void successfulAuthentication(HttpServletRequest request,
                                        HttpServletResponse response,
                                        FilterChain chain,
                                        Authentication authResult) throws ... {

    // 1. Store authentication in SecurityContext for this thread
    SecurityContext context = this.securityContextHolderStrategy.createEmptyContext();
    context.setAuthentication(authResult);
    this.securityContextHolderStrategy.setContext(context);

    // 2. Persist SecurityContext (saves to HTTP session by default)
    this.securityContextRepository.saveContext(context, request, response);

    // 3. Remember-me cookie (if configured)
    this.rememberMeServices.loginSuccess(request, response, authResult);

    // 4. Publish ApplicationEvent — LoginSuccessEvent
    if (this.eventPublisher != null) {
        this.eventPublisher.publishEvent(
            new InteractiveAuthenticationSuccessEvent(authResult, this.getClass()));
    }

    // 5. Redirect/respond via success handler
    this.successHandler.onAuthenticationSuccess(request, response, authResult);
}
```

## Layer 10: Success and Failure Handlers — The Response Strategy

```java
/**
 * LAYER 10A: AuthenticationSuccessHandler — what happens after successful login.
 *
 * Default: SavedRequestAwareAuthenticationSuccessHandler
 *   — checks if user was redirected to login from a protected page
 *   — if YES, redirects back to the original page (saved in session by ExceptionTranslationFilter)
 *   — if NO, redirects to defaultSuccessUrl
 */
public interface AuthenticationSuccessHandler {
    void onAuthenticationSuccess(HttpServletRequest request,
                                  HttpServletResponse response,
                                  Authentication authentication)
            throws IOException, ServletException;
}

// Production custom success handler — returns JSON instead of redirect (for SPA/API)
@Component
@RequiredArgsConstructor
public class JsonAuthenticationSuccessHandler implements AuthenticationSuccessHandler {

    private final ObjectMapper objectMapper;
    private final JwtTokenProvider jwtTokenProvider; // Your JWT utility

    @Override
    public void onAuthenticationSuccess(HttpServletRequest request,
                                        HttpServletResponse response,
                                        Authentication authentication)
            throws IOException {

        UserPrincipal principal = (UserPrincipal) authentication.getPrincipal();

        // Generate JWT and return it in JSON response body
        String token = jwtTokenProvider.generateToken(authentication);

        response.setContentType(MediaType.APPLICATION_JSON_VALUE);
        response.setStatus(HttpServletResponse.SC_OK);

        objectMapper.writeValue(response.getWriter(), Map.of(
            "token", token,
            "username", principal.getUsername(),
            "roles", authentication.getAuthorities().stream()
                        .map(GrantedAuthority::getAuthority)
                        .collect(Collectors.toList())
        ));
    }
}

/**
 * LAYER 10B: AuthenticationFailureHandler — what happens after failed login.
 *
 * Default: SimpleUrlAuthenticationFailureHandler
 *   — redirects to /login?error
 *   — stores AuthenticationException in session so the login page can display it
 */
@Component
@RequiredArgsConstructor
public class JsonAuthenticationFailureHandler implements AuthenticationFailureHandler {

    private final ObjectMapper objectMapper;

    @Override
    public void onAuthenticationFailure(HttpServletRequest request,
                                        HttpServletResponse response,
                                        AuthenticationException exception)
            throws IOException {

        response.setContentType(MediaType.APPLICATION_JSON_VALUE);
        response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);

        // Map specific exception types to meaningful error codes
        String errorCode = switch (exception) {
            case BadCredentialsException e -> "INVALID_CREDENTIALS";
            case DisabledException e -> "ACCOUNT_DISABLED";
            case LockedException e -> "ACCOUNT_LOCKED";
            case CredentialsExpiredException e -> "PASSWORD_EXPIRED";
            default -> "AUTHENTICATION_FAILED";
        };

        objectMapper.writeValue(response.getWriter(), Map.of(
            "error", errorCode,
            "message", exception.getMessage(),
            "timestamp", Instant.now().toString()
        ));
    }
}
```

## Layer 11: Session Management — `SessionFixationProtectionStrategy`

```java
/**
 * LAYER 11: Session Fixation Protection — a critical security mechanism.
 *
 * Session fixation attack: attacker sets a known session ID in victim's browser,
 * victim logs in, session is now authenticated — attacker uses the known ID.
 *
 * Spring Security defeats this by creating a NEW session after authentication,
 * migrating the old session's attributes (like the saved request) to the new one.
 *
 * Called inside AbstractAuthenticationProcessingFilter:
 *   sessionStrategy.onAuthentication(authResult, request, response)
 *
 * SessionAuthenticationStrategy implementations:
 *   - ChangeSessionIdAuthenticationStrategy (default, Servlet 3.1+)
 *       — calls request.changeSessionId() — same session object, new ID
 *       — more efficient than creating a new session
 *   - SessionFixationProtectionStrategy (legacy)
 *       — creates new HttpSession, copies attributes
 *   - NullAuthenticatedSessionStrategy
 *       — does nothing — use for stateless (JWT) apps
 *   - CompositeSessionAuthenticationStrategy
 *       — chains multiple strategies together
 */
@Bean
public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
    http
        .sessionManagement(session -> session
            // Session fixation protection strategy
            .sessionFixation().changeSessionId() // Default — most efficient

            // Session creation policy
            .sessionCreationPolicy(SessionCreationPolicy.IF_REQUIRED) // Default
            // IF_REQUIRED: create session when needed
            // STATELESS: never create session (for REST APIs with JWT)
            // ALWAYS: always create session
            // NEVER: never create, but use if it exists

            // Concurrent session control — prevent account sharing
            .maximumSessions(1)                 // Only 1 active session per user
            .maxSessionsPreventsLogin(false)    // false = kick old session (default)
                                                // true = reject new login
            .expiredUrl("/login?sessionExpired=true")
        );
    return http.build();
}
```

## Layer 12: `SecurityContextRepository` — Persistence Between Requests

```java
/**
 * LAYER 12: SecurityContextRepository — how authentication persists across requests.
 *
 * Without this, the user would need to log in on every single request.
 * The repository saves the SecurityContext after login and loads it on subsequent requests.
 *
 * SecurityContextPersistenceFilter (or SecurityContextHolderFilter in newer versions)
 * runs at the TOP of the filter chain — before any other filter — to restore context:
 *
 *   Request arrives → SecurityContextPersistenceFilter:
 *     1. Load SecurityContext from repository (reads from HTTP session)
 *     2. Set it on SecurityContextHolder
 *     3. chain.doFilter() — rest of filters see the authenticated context
 *     4. After response: save context back to repository, clear holder
 *
 * Implementations:
 *   HttpSessionSecurityContextRepository (default) — stores in HTTP session
 *   RequestAttributeSecurityContextRepository — stores in request attribute (single request)
 *   NullSecurityContextRepository — stateless (JWT apps), nothing is persisted
 *   DelegatingSecurityContextRepository — try multiple strategies
 */

// For traditional session-based apps — default, no config needed
// But explicitly configured here for clarity:
@Bean
public SecurityContextRepository securityContextRepository() {
    return new HttpSessionSecurityContextRepository();
    // Stores context as: session.getAttribute("SPRING_SECURITY_CONTEXT")
}

// For stateless JWT REST APIs:
@Bean
public SecurityContextRepository statelessContextRepository() {
    return new NullSecurityContextRepository();
    // Reads from JWT on every request, never saves to session
}

// Hybrid — saves to request attribute AND session (transition migration pattern)
@Bean
public SecurityContextRepository hybridContextRepository() {
    return new DelegatingSecurityContextRepository(
        new RequestAttributeSecurityContextRepository(), // Fast in-request lookup
        new HttpSessionSecurityContextRepository()       // Session-backed persistence
    );
}
```

## Layer 13: `RememberMeServices` — Persistent Login

```java
/**
 * LAYER 13: RememberMeServices — "keep me logged in" functionality.
 *
 * Called in successfulAuthentication() → rememberMeServices.loginSuccess()
 * Implemented as a separate filter: RememberMeAuthenticationFilter
 *   — runs if no authentication in SecurityContext yet
 *   — extracts remember-me cookie → verifies → sets authentication
 *
 * Two implementations:
 *   TokenBasedRememberMeServices: HMAC token (username+expiry+password+key)
 *     — Stateless, but invalidated if password changes
 *   PersistentTokenBasedRememberMeServices: DB-backed token series
 *     — More secure, supports token rotation, detects theft
 */
@Configuration
public class RememberMeConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http,
                                            PersistentTokenRepository tokenRepo) throws Exception {
        http
            .rememberMe(rm -> rm
                // PersistentToken strategy — production recommended
                .tokenRepository(tokenRepo)
                .tokenValiditySeconds(30 * 24 * 60 * 60) // 30 days
                .rememberMeParameter("remember-me")        // Form field name
                .rememberMeCookieName("REMEMBER_ME")       // Cookie name
                .useSecureCookie(true)                     // HTTPS only
                .key("your-secret-key-min-32-chars-long")  // HMAC key for token signing
                // userDetailsService needed for PersistentToken strategy:
                .userDetailsService(userDetailsService())
            );
        return http.build();
    }

    // JdbcTokenRepositoryImpl requires a persistent_logins table in your DB
    @Bean
    public PersistentTokenRepository tokenRepository(DataSource dataSource) {
        JdbcTokenRepositoryImpl repo = new JdbcTokenRepositoryImpl();
        repo.setDataSource(dataSource);
        repo.setCreateTableOnStartup(false); // Create table via Flyway/Liquibase instead
        return repo;
    }
}
```

## Layer 14: The Complete Security Configuration — Wiring Everything Together

```java
/**
 * LAYER 14: Production-Grade SecurityFilterChain Configuration
 *
 * SecurityFilterChain replaces the deprecated WebSecurityConfigurerAdapter (since 5.7).
 * You define beans instead of extending a class — more composable and testable.
 */
@Configuration
@EnableWebSecurity
@EnableMethodSecurity(prePostEnabled = true) // Enable @PreAuthorize, @PostAuthorize
@RequiredArgsConstructor
public class SecurityConfig {

    private final CustomUserDetailsService userDetailsService;
    private final JsonAuthenticationSuccessHandler successHandler;
    private final JsonAuthenticationFailureHandler failureHandler;
    private final PasswordEncoder passwordEncoder;

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            // CSRF: enable for browser clients, disable for stateless APIs
            .csrf(csrf -> csrf
                .csrfTokenRepository(CookieCsrfTokenRepository.withHttpOnlyFalse())
                // CookieCsrfTokenRepository puts CSRF token in a cookie readable
                // by JS frameworks (Angular, React) — they send it back as X-XSRF-TOKEN header
            )

            // Authorization rules — evaluated top to bottom, FIRST MATCH WINS
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/login", "/register", "/actuator/health").permitAll()
                .requestMatchers("/admin/**").hasRole("ADMIN")
                .requestMatchers("/api/**").hasAnyRole("USER", "ADMIN")
                .requestMatchers(HttpMethod.GET, "/public/**").permitAll()
                .anyRequest().authenticated()
            )

            // Form login configuration
            .formLogin(form -> form
                .loginPage("/login")                          // Custom login page URL
                .loginProcessingUrl("/perform-login")         // Where form POSTs to
                .usernameParameter("email")                   // Form field names
                .passwordParameter("passwd")
                .successHandler(successHandler)               // Custom success behavior
                .failureHandler(failureHandler)               // Custom failure behavior
                .failureUrl("/login?error=true")              // Simple redirect alternative
                .defaultSuccessUrl("/dashboard", false)       // false = only if no saved request
                .permitAll()                                   // Allow unauthenticated access to login URL
            )

            // Logout configuration
            .logout(logout -> logout
                .logoutUrl("/logout")
                .logoutRequestMatcher(new AntPathRequestMatcher("/logout", "POST"))
                .logoutSuccessUrl("/login?logout=true")
                .invalidateHttpSession(true)                  // Destroy session
                .deleteCookies("JSESSIONID", "REMEMBER_ME")  // Clean up cookies
                .clearAuthentication(true)
                .addLogoutHandler(customLogoutHandler())       // Custom cleanup
                .logoutSuccessHandler(customLogoutSuccessHandler()) // Custom response
            )

            // Session management
            .sessionManagement(session -> session
                .sessionFixation().changeSessionId()
                .sessionCreationPolicy(SessionCreationPolicy.IF_REQUIRED)
                .maximumSessions(1).expiredUrl("/login?sessionExpired=true")
            )

            // Exception handling — what happens when auth fails or access is denied
            .exceptionHandling(ex -> ex
                .authenticationEntryPoint(customAuthEntryPoint())  // 401 handler
                .accessDeniedHandler(customAccessDeniedHandler())  // 403 handler
            );

        return http.build();
    }

    @Bean
    public AuthenticationManager authenticationManager() {
        DaoAuthenticationProvider provider = new DaoAuthenticationProvider();
        provider.setUserDetailsService(userDetailsService);
        provider.setPasswordEncoder(passwordEncoder);
        return new ProviderManager(provider);
    }

    // 401 — Unauthenticated: request a resource without being logged in
    @Bean
    public AuthenticationEntryPoint customAuthEntryPoint() {
        return (request, response, authException) -> {
            response.setContentType(MediaType.APPLICATION_JSON_VALUE);
            response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
            response.getWriter().write("""
                {"error": "UNAUTHORIZED", "message": "Please log in to access this resource"}
                """);
        };
    }

    // 403 — Forbidden: authenticated but lacks required role
    @Bean
    public AccessDeniedHandler customAccessDeniedHandler() {
        return (request, response, accessDeniedException) -> {
            response.setContentType(MediaType.APPLICATION_JSON_VALUE);
            response.setStatus(HttpServletResponse.SC_FORBIDDEN);
            response.getWriter().write("""
                {"error": "FORBIDDEN", "message": "Insufficient permissions"}
                """);
        };
    }
}
```

## Layer 15: Events, Auditing, and Application Events

```java
/**
 * LAYER 15: Spring Security ApplicationEvents — observability hooks.
 *
 * Spring Security publishes events throughout the authentication lifecycle.
 * These are perfect for audit logging, metrics, and alerting.
 *
 * Published events:
 *   AuthenticationSuccessEvent — after successfulAuthentication()
 *   AbstractAuthenticationFailureEvent (subclasses per exception type)
 *     └── AuthenticationFailureBadCredentialsEvent
 *     └── AuthenticationFailureLockedEvent
 *     └── AuthenticationFailureDisabledEvent
 *     └── AuthenticationFailureExpiredEvent
 *   InteractiveAuthenticationSuccessEvent — form login specifically
 *   LogoutSuccessEvent — after logout
 */
@Component
@RequiredArgsConstructor
@Slf4j
public class SecurityAuditEventListener {

    private final AuditLogRepository auditLogRepository;
    private final MeterRegistry meterRegistry;

    @EventListener
    public void onAuthenticationSuccess(AuthenticationSuccessEvent event) {
        Authentication auth = event.getAuthentication();
        WebAuthenticationDetails details = (WebAuthenticationDetails) auth.getDetails();

        auditLogRepository.save(AuditLog.builder()
            .event("LOGIN_SUCCESS")
            .username(auth.getName())
            .ipAddress(details != null ? details.getRemoteAddress() : "unknown")
            .timestamp(Instant.now())
            .build());

        meterRegistry.counter("auth.success").increment();
        log.info("Successful login: user={}", auth.getName());
    }

    @EventListener
    public void onAuthenticationFailure(AbstractAuthenticationFailureEvent event) {
        String username = event.getAuthentication().getName();
        String failureType = event.getException().getClass().getSimpleName();

        auditLogRepository.save(AuditLog.builder()
            .event("LOGIN_FAILURE")
            .username(username)
            .failureReason(failureType)
            .timestamp(Instant.now())
            .build());

        meterRegistry.counter("auth.failure", "type", failureType).increment();
        log.warn("Failed login attempt: user={}, reason={}", username, failureType);
    }
}
```

## Layer 16: Testing Spring Security Authentication

```java
/**
 * LAYER 16: Testing — how to write reliable tests for your security config.
 *
 * spring-security-test provides @WithMockUser, @WithUserDetails,
 * MockMvc SecurityMockMvcConfigurer, and formLogin() / logout() RequestBuilders.
 */
@SpringBootTest
@AutoConfigureMockMvc
class AuthenticationIntegrationTest {

    @Autowired MockMvc mockMvc;

    @Test
    @DisplayName("Successful login redirects to dashboard")
    void successfulLogin() throws Exception {
        mockMvc.perform(post("/perform-login")
                .param("email", "alice@example.com")
                .param("passwd", "correctPassword")
                .with(csrf())) // Include CSRF token — required if CSRF protection is enabled
            .andExpect(status().is3xxRedirection())
            .andExpect(redirectedUrl("/dashboard"));
    }

    @Test
    @DisplayName("Wrong password returns 401 with error response")
    void failedLogin() throws Exception {
        mockMvc.perform(post("/perform-login")
                .param("email", "alice@example.com")
                .param("passwd", "wrongPassword")
                .with(csrf()))
            .andExpect(status().isUnauthorized())
            .andExpect(jsonPath("$.error").value("INVALID_CREDENTIALS"));
    }

    @Test
    @DisplayName("Protected endpoint accessible with valid session")
    @WithUserDetails("alice@example.com") // Calls loadUserByUsername() — uses real UserDetails
    void protectedEndpointWithValidSession() throws Exception {
        mockMvc.perform(get("/api/profile"))
            .andExpect(status().isOk());
    }

    @Test
    @DisplayName("Admin endpoint denied for regular user")
    @WithMockUser(username = "bob", roles = {"USER"}) // Bypasses UserDetailsService — fast unit test
    void adminEndpointDeniedForUser() throws Exception {
        mockMvc.perform(get("/admin/users"))
            .andExpect(status().isForbidden());
    }

    @Test
    @DisplayName("Full login-then-access session flow")
    void fullLoginFlow() throws Exception {
        // Perform login and capture the session cookie
        MvcResult loginResult = mockMvc.perform(post("/perform-login")
                .param("email", "alice@example.com")
                .param("passwd", "correctPassword")
                .with(csrf()))
            .andExpect(status().is3xxRedirection())
            .andReturn();

        MockHttpSession session = (MockHttpSession) loginResult.getRequest().getSession();

        // Use the session in subsequent requests
        mockMvc.perform(get("/api/profile").session(session))
            .andExpect(status().isOk())
            .andExpect(jsonPath("$.username").value("alice@example.com"));
    }
}
```

## The Complete Mental Model

To cement everything, here's how all layers connect in the request lifecycle:

```
HTTP Request (POST /perform-login)
         │
         ▼
SecurityContextPersistenceFilter          ← Layer 12: loads context from session (empty for new login)
         │
         ▼
UsernamePasswordAuthenticationFilter      ← Layer 8: intercepts POST /perform-login
         │
         ├── requiresAuthentication()     → true
         ├── attemptAuthentication()
         │       ├── Extract params        ← obtainUsername(), obtainPassword()
         │       ├── Create token          ← UPAuthToken(user, pass, unauthenticated) [Layer 6]
         │       ├── setDetails()          ← WebAuthenticationDetails(IP, sessionId) [Layer 6]
         │       └── authManager.authenticate() ← [Layer 7]
         │               └── ProviderManager
         │                       └── DaoAuthenticationProvider ← [Layer 5]
         │                               ├── loadUserByUsername() ← [Layer 2]
         │                               ├── preAuthChecks()    ← [Layer 2: enabled/locked/expired]
         │                               ├── passwordEncoder.matches() ← [Layer 4]
         │                               ├── postAuthChecks()   ← [Layer 2: credentials non-expired]
         │                               └── return UPAuthToken(UserDetails, null, roles)
         │
         ├── sessionStrategy.onAuthentication() ← Layer 11: new session ID, session fixation protection
         │
         └── successfulAuthentication()
                 ├── SecurityContextHolder.setContext(auth) ← Layer 1
                 ├── securityContextRepository.save()       ← Layer 12: persists to session
                 ├── rememberMeServices.loginSuccess()      ← Layer 13: remember-me cookie
                 ├── eventPublisher.publishEvent()          ← Layer 15: audit events
                 └── successHandler.onAuthenticationSuccess() ← Layer 10: redirect/JSON response
```

Every layer you've now mastered has a clear reason to exist, a precise place in the chain, and clean extension points for production customization. The beauty of Spring Security's design is that you can swap out any single layer — your `UserDetailsService`, your `AuthenticationProvider`, your success handler — without touching anything else.
